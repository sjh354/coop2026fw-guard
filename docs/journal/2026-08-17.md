## EXP-8 — 발표 자료 리뷰 질문 4개 보강

사용자가 `results_summary.md` D5(실패 사례 6건)/D4(flip rate)/D7(calibration)를 검토하다가
4가지 질문을 던짐:

1. 실패 사례가 6건뿐이고 전부 ko — 12~18건으로 늘릴 수 있는가?
2. 모델×카테고리별 FP/FN 집계가 있는가?
3. flip rate가 harmful→safe(우회)와 safe→harmful(과차단) 방향 분해가 안 돼 있다.
4. confidence 분포/threshold sweep이 있는가?

**먼저 확인한 것**: 로컬에 이미 있는 데이터로 GPU 재실행 없이 4개 다 답이 나오는지 조사.
- `results/multilingual_{model}.csv` + `multilingual_variants_{model}.csv`에 `confidence`,
  `raw_output`이 이미 있음 → 1, 4번 재료 확보.
- `~/.cache/huggingface/hub/datasets--ToxicityPrompts--PolyGuardPrompts/blobs/`에 원본
  parquet(29,325행, 17개 언어 전체)이 **이미 로컬 캐시**돼 있었음 — `subcategory`/
  `prompt_categories`(S-code) 필드로 정답 카테고리 확보 가능, id+language로 join. → 2번 재료.
- `multilingual_variants_{model}.csv`(210 base_id)가 `multilingual_{model}.csv`(baseline)와
  100% join 가능 → 3번 재료.

전부 기존 산출물 조합으로 해결 가능하다고 판단, 사용자에게 시간 추산(1~1.5시간) 보고 후
진행 승인받음.

**실행**:
- `exp/category_fp_fn.py` 신규 — llamaguard(`unsafe\nS8` 파싱)/polyguard(`Request safety
  violations: S2` 정규식)/sguard(`Crime:unsafe, ...` 카테고리별 safe/unsafe) raw_output에서
  예측 카테고리 추출, PolyGuardPrompts parquet + IndoSafety `source_label`에서 정답 카테고리
  join. PGPrompts en/ko(메인) + Track A(5언어) + IndoSafety(id)만 커버 — MultiJail/RTP-LX
  소스는 세부 카테고리가 원본에 없어 제외(명시). 결과: 세 모델 다 S10(Hate)/사회적 고정관념이
  FN 1위, llamaguard·polyguard는 S8(IP)이 FP 1위.
- `exp/flip_direction_multilingual.py` 신규 — 기존 `flip_compare_multilingual.py`는 flip
  여부만 셌는데 true_label을 같이 join해 bypass(harmful→safe)/overblock(safe→harmful)로
  분리. 결과: 세 모델 다 bypass가 overblock보다 2.7~15배 높음 — obfuscation은 우회 공격
  벡터라는 정성적 결론이 수치로 확인됨(SGuard가 가장 비대칭적: 0.2155 vs 0.0143).
- `exp/confidence_threshold_sweep.py` 신규 — PGPrompts en/ko(+다국어) confidence 분포와
  threshold sweep(0.5~0.95) 계산. threshold=0.9에서 coverage 61~94% 유지하며 F1 전 셀
  개선 확인. llamaguard ko는 정답/오답 confidence 격차가 작아(0.06p) 개선폭이 가장 작음 —
  카테고리별 threshold 튜닝 제안은 모델별 효과 차이가 있을 것으로 예상, 검증은 범위 밖.
- `exp/failure_cases_multilingual.py` 신규 — 오분류 전량(1499행) candidate pool 추출 후
  수작업으로 12건 큐레이션(`docs/failure_cases_multilingual.md`). PolyGuardPrompts가
  17개 언어 병렬 번역이라는 점을 활용해 **같은 base_id가 2~3개 언어에서 동시에 실패**하는
  사례를 우선 선정 — 개별 언어 노이즈가 아니라 프롬프트 스타일 자체의 체계적 약점임을
  보여줌(반문형 차별 질문, 게임 브랜드 위장 해킹 요청, 허구 인물+PII 조합). 새로 발견한
  패턴: "AI 역할극" 강조체 프레이밍이 콘텐츠와 무관하게 FP를 유발(es/ru/hi 3개 언어에서
  동일 base_id 재현, hi는 S1~S13 13개 카테고리 동시 트리거라는 degenerate 출력까지 관찰).

**문서 갱신**: `results_summary.md`에 D11(카테고리 FP/FN)/D12(flip 방향 분해)/D13(confidence
threshold sweep) 신설, D10(메타데이터)을 D14로 재번호(신설 섹션이 D9와 D10 사이에 들어가면서
