# 2026-08-19

## 발표 리뷰 중 발견: `exp/category_fp_fn.py` Track A join 버그

슬라이드 10(모델×카테고리별 FP/FN)을 리뷰하다가 분모(총 데이터셋 개수)가 슬라이드에 안 적혀
있다는 지적이 나와서 `exp/category_fp_fn.py` 산출물(`results/final/category_fp_fn.csv`)의
출처를 역추적함.

**분모 자체는 확인됨**: PGPrompts en(1,699) + ko(1,699) + Track A(es/hi/th/ar/ru, 150) +
IndoSafety(id, 20) = 총 3,568행. MultiJail/RTP-LX는 세부 카테고리가 없어 제외 — 이 부분은
슬라이드 설명과 일치.

**버그 발견**: `track_a_fp_fn()`이 Track A 예측 결과를 PolyGuardPrompts 정답 카테고리와
`base_id`만으로 merge하고 있었는데, `data/multilingual_base.csv`는 같은 `base_id`가
언어(es/hi/th/ar/ru)별로 5행 중복돼 있다(`source_id`는 5행 다 동일값). `lang`을 join key에서
빼먹어서 Track A의 실제 150행이 750행으로 팬아웃되고, 거기서 나온 모든 FP/FN 카테고리 카운트가
정확히 5배 부풀어 있었다. en/ko(메인 1,699개×2) 구간은 별도 함수(`pgprompts_fp_fn`)를 쓰고
있어 이 버그의 영향을 받지 않음.

**영향 확인** (직접 재계산으로 검증):
- Llama Guard S10(Hate) FN: 버그 상태 333건 → 정정 후 189건 (en 48 + ko 105 + TrackA
  36 = 189, 정확히 일치)
- PolyGuard S10 FN: 106건 → 58건

**수정**: `on="base_id"` → `on=["base_id", "lang"]`로 join key 변경, `exp/category_fp_fn.py`
재실행 → `results/final/category_fp_fn.csv`, `results/final/category_fp_fn.meta.json` 갱신.

**정정 후 가장 중요한 변화 — FN 1위 카테고리가 바뀜**:
- 정정 전: 3모델 다 **S10(Hate)이 FN 1위**
- 정정 후: 3모델 다 **S2(Non-Violent Crimes)가 FN 1위**, S10은 2위로 밀림
  (llamaguard: S2 210 > S10 189, polyguard: S2 65 > S10 58, sguard: S2 88 > S10 64)

FP 쪽은 llamaguard는 S8(IP) 1위 그대로지만, **polyguard는 S8이 1위(53건)에서 4위(25건)로
밀려나고** S2(35)/S7(34)/S10(31)이 새 top-3가 됨. SGuard는 정정 전 "Crime·Privacy 동률
1위"였던 게 정정 후 Crime(54)이 단독 1위로 바뀜.
