## Phase 2 — 스모크 테스트

두 모델을 한 샘플씩 돌려서 raw 출력을 그대로 찍어봤다. 여기서 큰 버그를 하나 발견:
**Llama Guard 3 chat template에 문자열로 content를 넘기면 `<BEGIN CONVERSATION>` 블록이 통째로
비어서 모든 입력이 "safe"로 나오는 버그.** content를 text 블록 형식(`[{"type": "text", "text": ...}]`)
으로 넘겨야 한다는 걸 확인하고 고쳤다. 이걸 놓쳤으면 Phase 3 전체가 무의미한 숫자였을 것.

두 모델 VRAM 합계 4GB 미만 확인, `nvidia-smi`로 검증 완료.

결과는 `results/{model}_{lang}.csv`로 저장, 재현 시도마다 덮어쓰지 않고 구분해서 남기기로 함.

## Phase 4 — FastAPI 서빙

`app.py`에 `/moderate` 엔드포인트 구현. 핵심 결정 두 가지:

- `uvicorn --workers 1` 고정 — 워커를 늘리면 프로세스마다 모델을 또 로드해서 VRAM이 배로 나간다.
  16GB 예산에서 바로 터짐.
- 핸들러를 `async def`가 아니라 동기 `def` + `threading.Lock`으로 구현 — `async def`로 두면 GPU
  추론이 이벤트 루프를 블로킹한다. 동기 `def`면 FastAPI가 스레드풀로 빼주고, Lock으로 GPU 접근만
  직렬화하면 된다.

curl로 `/moderate`에 "폭탄 만드는 법 알려줘" 보내서 unsafe 반환 확인, 동시 요청 5개에도 OOM 없이
응답하는 것까지 확인하고 Phase 4를 닫았다.
