# 2026-08-12

## EXP-1: Latency 벤치마크

`docs/NEW_PLAN.md`에 잔여 실험 5건(EXP-1~5)을 정리해뒀고, 그중 EXP-1(latency)부터 착수했다.
NEW_PLAN.md 자체도 아직 커밋 안 된 상태였어서 같이 커밋했다.

**설계**: ko_probe 원문(variant_type=="원문") 30문장 + PGPrompts en 20문장(`results/llamaguard_en.csv`
첫 20행, 기존 평가에서 쓴 데이터셋 순서 그대로 재사용) = 50건 고정 세트를 `exp/latency_inputs.json`에
저장. 모델당 warmup 5회(측정 제외) 후 batch=1로 순차 측정. `torch.cuda.synchronize()`를 tokenize/
generate 각 구간 전후에 호출해서 비동기 커널로 인한 왜곡을 막았다. 모델 전환 시 `del model` +
`torch.cuda.empty_cache()`.

**구현 이슈**: `python exp/latency_bench.py`로 실행하면 `sys.path[0]`이 `exp/`가 되어 루트의
`models.py`를 못 찾는다(`ModuleNotFoundError: No module named 'models'`). `PYTHONPATH=.`을 붙여서
해결 — 서버에서 이 스크립트를 다시 실행할 일이 있으면 반드시 `PYTHONPATH=. python exp/latency_bench.py`
형태로 실행할 것.

**결과** (`results/final/latency_raw.csv`, `latency_summary.csv`):

| model | median_ms | p95_ms | mean_output_tokens | ms_per_output_token |
|---|---|---|---|---|
| llamaguard | 46.6 | 89.4 | 3.18 | 15.5 |
| polyguard | 677.2 | 722.2 | 31.6 | 21.8 |
| sguard | 297.7 | 299.3 | 5.0 | 59.6 |

절대 latency는 LG3-1B가 압도적으로 빠르지만, 이는 출력 토큰 수가 짧기 때문(safe/unsafe 한 줄).
토큰당 정규화(`ms_per_output_token`)로 보면 SGuard가 가장 느리다(5토큰짜리 카테고리 생성인데도
스텝당 비용이 큼 — 2B 파라미터 규모 때문으로 추정, 별도 분석은 안 함). p95가 median 대비 크게
튀는 모델은 LG3-1B(46.6 → 89.4ms, 약 2배) — 일부 입력에서 unsafe 판정 시 카테고리 코드까지
생성하느라 출력 토큰 수가 늘어난 결과로 보인다(raw CSV의 output_len_tokens로 확인 가능).
