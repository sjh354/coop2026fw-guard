Safety Guard 모델 3종 비교 — EXP-1~5 결과 요약

PolyGuard-Qwen-Smol / Llama-Guard-3-1B / SGuard-ContentFilter-2B-v1을 latency, response harmfulness, confidence calibration, 통계적 유의성, 언어 간 변형 취약성 5개 축에서 비교했다.

● results/final/ 동결됨 tag: presentation-freeze commit: 7dc63c3 2026-08-12

Executive Summary

  • Latency: 절대 속도는 LG3-1B가 가장 빠르다(median 46.6ms). 그러나 토큰당(ms/token) 기준으로는 PolyGuard가 가장 느리다(21.8ms/token) — 출력 포맷 길이(4-field, 평균 31.6토큰) 차이가 절대 latency 순위를 왜곡한다.
  • Response harmfulness는 세 모델 모두 prompt harmfulness보다 어렵다(F1 평균 -0.19~-0.30p). LG3-1B가 response 축에서 가장 취약(en F1 0.75→0.45).
  • 세 모델 다 과신(overconfident) — ECE 0.10~0.16, confidence 0.9대에도 실제 accuracy는 0.6~0.8대. LG3-1B가 가장 심하게 과신한다(ECE 0.1614).
  • McNemar 검정 결과 관측된 F1 격차는 전부 통계적으로 유의하다(보정 후 p<0.01). 단 ko_probe(변형 프롬프트)에서는 LG3-1B가 SGuard-v1보다 유의하게 우세해 PGPrompts 기준 순위가 뒤집힌다.
  • 영어 변형 프로브 결과, "번역투(학습 분포 이탈)" 취약성은 한국어 특유였다(PolyGuard 26.7%→11.5%, SGuard 23.3%→3.9%). 반대로 leet-speak·code-switching은 언어 무관하거나 영어에서 더 취약해지는 경우도 있었다 — 변형 공격 취약성은 단일 원인으로 설명되지 않는다.
  • 모델 간 판단 일치도(Cohen's κ)는 전반적으로 낮다(0.13~0.65) — 세 모델이 서로 다른 판정 기준을 학습했음을 시사한다.

해석 confidence가 0.9대인 구간에서도 실제 accuracy는 0.6~0.8대에 머문다 — demo가 보여주는 confidence 숫자를 그대로 "이 판정이 90% 맞다"로 읽으면 안 된다. LG3-1B가 가장 심하게 과신하며, 이는 EXP-2에서 확인한 response harm 축 취약성과 함께 LG3-1B의 신뢰도를 낮추는 근거로 제시할 수 있다. reliability diagram 원본은 figures/reliability_*.png 참고.

04McNemar 유의성 검정

주요 비교쌍에 대해 paired 2×2 분할표 + McNemar 검정(불일치 셀 합<25면 exact, 아니면 continuity-corrected chi-square). ko_probe 3-way pairwise는 Bonferroni 보정(α=0.05/3). GPU 재실행 없음, 기존 예측 CSV만 사용.

05영어 변형 프로브 (선택)

ko_probe 변형 취약성이 한국어 특유인지 언어 무관인지 분리하기 위해, 문화특이적 카테고리 (age, origin 중 홍어/b09 — 영어 대응 슬러 부재로 confound 우려)를 제외한 26문장을 영어로 옮기고 5-variant를 재적용 (26×5=130건). GPU 재실행, parse 실패율 0%.

해석 번역투(학습 분포 이탈) 취약성은 한국어 특유였다 — 영어로 옮기면 세 모델 모두 flip rate가 크게 떨어진다(PolyGuard -15.2p, SGuard -19.5p, LG3-1B -6.2p). 반대로 leet-speak(우회표기)·code-switching은 언어 무관하거나 오히려 영어에서 더 취약해진다(SGuard code-switching +10.2p, 띄어쓰기 +12.1p; LG3-1B 우회표기 +4.8p) — 표층 패턴(문자 치환·언어 혼용) 의존형 취약성은 언어 공통적이라는 뜻이다.
한계 base 문장이 26개뿐이라(ko_probe 30개 대비 4개 적음) variant당 표본이 작다(en=26쌍, ko=30쌍). 번역 자체의 자연스러움 차이가 결과에 섞여 있을 가능성도 배제할 수 없다.

＋한계 및 발표 시 유의사항

  • EXP-4/EXP-5는 GPU 재실행 없이 기존 예측 CSV를 재활용한 순수 통계 계산 — 모델이 재학습되거나 업데이트되면 수치가 달라질 수 있다.
  • EXP-5의 en_probe는 ko_probe와 base 문장 수가 다르다(26 vs 30) — 절대 flip rate 비교가 아니라 변화 방향과 패턴 비교로 읽어야 한다.
  • reason 필드(Phase 7 demo)는 모델의 실제 판정 근거가 아니라 카테고리→템플릿 매핑이다 — 발표에서 "모델이 이렇게 설명했다"로 오해되지 않도록 주의.
  • 동결(presentation-freeze) 이후 발견되는 문제는 수치를 고치지 않고 발표 자료 각주로 처리한다.
